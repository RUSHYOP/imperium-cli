## Overview

Imperium CLI supports authentication via **Microsoft Entra ID** (formerly Azure AD). Organizations can publish skills, MCP server configs, and presets that are only accessible to authenticated members of allowed domains.

When browsing the registry, items that require authentication are tagged with a **`[private]`** badge.

## Sign in

```bash [Terminal]
imperium login
```

This opens your browser for Microsoft sign-in. After authenticating, the CLI stores a token locally and you're ready to access organization-restricted content.

## Check your status

```bash [Terminal]
imperium whoami
```

Shows your current authentication status — email address and domain.

## Sign out

```bash [Terminal]
imperium logout
```

Clears your stored credentials.

## How it works

::steps
### Browser-based OAuth

When you run `imperium login`, a local HTTP server starts and your browser opens to Microsoft's sign-in page. Authentication uses **OAuth 2.0 with PKCE** — no client secrets are stored or transmitted.

### Token storage

After sign-in, tokens are cached at `~/.imperium/auth.json`. They're used automatically for subsequent commands that access restricted content.

### Transparent access

Once logged in, all CLI commands work the same — `list`, `add`, `setup`, `search`. Restricted items will appear alongside public ones, and `imperium add` will fetch them seamlessly.

### Token refresh

Tokens are refreshed automatically when they expire. If a refresh fails, you'll be prompted to run `imperium login` again.
::

## When do you need authentication?

You **don't** need to log in for public content. The 118+ skills, 6 MCP server configs, and instruction files in the public registry are available to everyone without authentication.

Authentication is only required when your organization has published restricted content that's gated behind domain-based access control.
